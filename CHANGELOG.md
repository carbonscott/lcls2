### Added

- Added hardware-free runs of hsd, epixquad1kfps and epixUHR through their own config code (`daq_sim up --det hsd|epixquad1kfps|epixUHR`). hsd: `Digitizer` installs `psdaq.sim.rogue_dev` under `drp -d sim://` as BEBDetector does, so `hsd_config.py` builds its `DrpPgpIlvRoot` on an emulated card, and `simhsdioc` serves the hsd's PVs (hsdpvs's) and does what its IOC does with them as far as `hsd_config` reads it back; `MemPoolSim` sends the hsd's event header, raw and fex streams, and `xtc2_check` compares every sample of `waveforms()` and every peak of `peaks()`; `configdb_seed` runs `hsd_config_store.py`, a script, against a configdb that contacts nothing. epixquad1kfps: a `rogue_dev` seed can make a register's low bits a device's answer (`{"response": v, "bits": n}`), which the camera's SPI PROM status needs. epixUHR: `MemPoolSim` packs each ASIC's pixels as psana's descrambler unpacks them, and `psdaq.sim.epixuhr_files` writes the PLL tables and pixel maps its store reads. Two config-code defects are fixed: `epixUHR_config.py`'s per-ASIC gain branches used an undefined `i`, so Configure raised `NameError` with its store's default on hardware too, and the ePixUHR stores read their files only from a facility path, which `EPIXUHR_CONFIG_DIR` now overrides (default unchanged). The RUNBOOK lists why tt, jungfrau, epixuhr3x2 and epixhr2x2 do not run yet. [#44](https://github.com/carbonscott/lcls2/pull/44)
- Added hardware-free runs of opal, piranha4, tb and epixquad through their own `<type>_config.py` (`daq_sim up --det opal|piranha4|tb|epixquad`): `psdaq.sim.rogue_dev` answers a camera link camera's serial commands from its seed file (`_uart`), and a seed can now be a string register's text, name a root whose class name starts with `_`, or sit on a device that another seed enables; `MemPoolSim` frames each type's subframes and `xtc2_check` compares every pixel (opal, piranha4, epixquad through `epix10ka_raw_3_0_1`) or every field of the event timing message (tb, through `ts_raw_2_1_0`). Two config-code defects that stopped these DRPs on hardware too are fixed: `tb_config.py` imports `lcls2_pgp_pcie_apps` through `psdaq.utils` and its `tb_connectionInfo` takes the alloc message `BEBDetector` passes, and `epixquad_config.py` imports `lcls2_pgp_pcie_apps` before `ePixQuad`, whose older axi-pcie-core made `DevRoot` fail at start. Not fixed: `epixquad_config.py` reads `user.pixel_map`, which `epixquad_config_store` no longer writes (it writes `user.pixel_map_raw`), so the simulated config DB entry adds that key (zeros, as the store's map is). The RUNBOOK lists why epixquad1kfps, tt, hsd, jungfrau and epixuhr3x2 do not run yet. [#39](https://github.com/carbonscott/lcls2/pull/39)
- Added web copies of the PyQt `hsdpva`, `dtica`, `daqstat`, `datadev_monitor` and `detector_protection_monitor` GUIs at `/gui/<name>`, and of the plot panels of `seqplot` and `seq_epixhr --plot` (not yet the Plot Options and axis menus pyqtgraph gives each panel), each checked by `check_gui_parity` with every mapped row driven by a headless-browser test against the simulated DAQ or a campaign simulator: `simdti` serves the PVs of `dticas`, `simslurm` answers the Slurm commands of daqmgr (the web `daqstat` never runs one), `simdatadev` makes `datadev_monitor`'s nodes local simulated ones (the web copy never starts ssh), `simdetprot` serves the protection IOC's PVs over loopback Channel Access, and `simhsd` now gives every HSD monitoring field its own value. `tdmpva` is not applicable: it imports `psdaq.pytdm`, which the tree does not have. The parity walk now refuses every remote shell and Slurm command, counts pyqtgraph plot panels, and counts a label that was not yet written as a display when the walk saw another label built by the same line written. [#37](https://github.com/carbonscott/lcls2/pull/37)
- Added web copies of the PyQt `deadca`, `partca`, `xpmpatt`, `tprca` and `pvatable` GUIs at `/gui/<name>`, each checked by `check_gui_parity` with rows from its source and an offscreen walk and every mapped row driven by a headless-browser test against the simulated DAQ or a campaign device simulator (`simtpr` serves the PVs of `tprcas`, `simhsd` those of `hsdpvs`; simxpm adds the stand-in PVs `deadca`, `partca` and `xpmpatt` read), and the check's `no-window` rule for `partca-sum.py` and `xpmca.py`, which raise before showing a window; the walk refuses every connection to another host. ### Changed

- Changed `daq_sim coverage` so an evidence record proves a row only if its files show the row ran: the record keeps each listed file's size and sha256 from when it was written, and a file changed since (a log may only grow) or not hashed voids it; a detector row needs a listed xtc2 file, read by the tool itself, whose Configure has a detector of that type, with at least 1000 L1Accepts holding its data and a BeginRun whose runinfo is the record's run, and a log of the DRP of that type naming the run; a program row needs that program's log (its stand-in's for a STAND-IN row) naming the run's xtc2 file or BeginRun time. `daq_sim up` heads each service's log with its `# CMDLINE:`, `daq_sim cycle` prints any row coverage would reject in the record it writes, and a rejection names the kind of file problem (`not xtc2`, `changed`, ...). [#38](https://github.com/carbonscott/lcls2/pull/38)
- Changed the web GUI parity check so the offscreen PyQt walk decides which controls the running GUI builds (a mapped row it never builds fails), every web test records the backend it ran against, and a mapped row counts only if its passing test ran against the simulated DAQ; `daq_sim up --segments N` runs a fakecam detector with N segments. [#33](https://github.com/carbonscott/lcls2/pull/33)
- Changed the TEB, MEB and DRP to detect a reused or overwritten RDMA buffer slot when it happens and report the source, slot and pulse IDs; `-k eb_slot_check=0` turns this off. @rclaus2 [#289](https://github.com/slac-lcls/lcls2/pull/289)
- Changed control's BeginRun phase 1 timeout from 6 s to 12 s, since fetching calibration constants can take several seconds. @rclaus2 [#269](https://github.com/slac-lcls/lcls2/pull/269)
- Changed the DAQ and psana tests to run on every push to a PR. @mavaylon1 [#267](https://github.com/slac-lcls/lcls2/pull/267)

### Fixed

- Fixed psana SMD callbacks restarting their step and event counters at chunk boundaries, which could skip selected steps or repeat event-selection windows in serial and MPI processing. @monarin [#287](https://github.com/slac-lcls/lcls2/pull/287)
- Fixed parallel psana hanging silently when the MPI layout leaves an EventBuilder with no BigData ranks. `Communicators` now rejects such layouts up front with the numbers spelled out. @amandashack [#249](https://github.com/slac-lcls/lcls2/pull/249)
- Fixed a multi-lane DRP stalling silently when one lane stops delivering, as in #273. The reader now logs, once, which lanes arrived and which are missing for the stuck event, and counts it in the `drp_num_lane_stalls` metric. A partial event left by the stall no longer survives a Reset or an evtCounter restart, where it used to combine with the next event into a duplicate transition and abort the DRP; such events are counted in `drp_num_stale_events`. @rclaus2 [#282](https://github.com/slac-lcls/lcls2/pull/282)
- Fixed `XtcMonitorServer` and `ShmemClient` not saying why `mq_open` failed. They now name the exceeded system limit (e.g. `fs.mqueue.msg_max`) or other cause and how to fix it, and errors no longer appear ahead of earlier output in logs. @rclaus2 [#276](https://github.com/slac-lcls/lcls2/pull/276)
