- Added hardware-free runs of seven more programs, each counted by `daq_sim coverage` from evidence at the commit: `daq_sim up --pvservers` runs the tree's own PV servers `bldcas` and `hpsdbuscas` under procmgr as lab3-bld.cnf does, and the cycle gets every PV name their source defines from them and puts one PV and reads it back while the run runs (R3b); `pvatable` on simhsd and `xpmpva` on simxpm run offscreen as GUIs on device stand-ins (R4), the walk naming a label by the object that holds it with its PV, simxpm serving the `PAddr`, `Us:RxAlign` and `SFPSTATUS` xpmpva reads at start and pulse IDs in `PATT:GROUPS`; simhsd stands in for `hsd134PVs` and simtpr for `tprioc` (R3), their PV names read from the C++ sources meson builds them from (simtpr now also serves the 10 names tprioc adds to tprcas's); and `daqstat` runs on simslurm's jobs for the processes of `daq_sim.cnf` (shims on its PATH, no Slurm controller), proven by 2 or more refreshes of its table during the run that match the cycle's own squeue reads (new rule R5, RUNBOOK §3d). [#STACK](https://github.com/carbonscott/lcls2/pull/STACK)
- Added `daq_sim matrix`, one command that runs the whole hardware-free matrix unattended (`psdaq.sim.matrix`, RUNBOOK §3k): one DAQ per detector type, in turn (`up --det <T>`, a recorded cycle of 1000 L1Accepts, `down`), with named assertions on its transitions, its DRP process, its counts (simxpm's L1Accepts, the TEB's recorded events, psana2's events and events with the type's data), the per-event check and its coverage evidence, and one line per type (node, job, run file, the three counts, verdicts); one run of the programs (`up --ami --pva --epics --udp --gui --pvservers` and `cycle --ami-shot`: the MEB, AMI, the system DRPs, the PyQt GUIs, the PV-server stand-ins and the GUIs on them, every check of the cycle, their evidence); then `daq_sim feature a`..`e` (c with `--ami-src`, d with `--hosts`; a feature that cannot run here, d without two hosts of the Slurm job, is NOT AVAILABLE, a failure, and starts nothing) and `daq_sim coverage`. It exits 0 only if every assertion passes, writes a JSON summary that keeps earlier results at the same HEAD so a section can be re-run alone (`--only`, `--types`, `--features`), and can take a `flock(2)` lock around each DAQ (`--lock`). `--break register|kill-drp|corrupt` shows it failing and naming the assertion: a register the simulated device reads back wrong at Configure (`PSDAQ_SIM_ROGUE_FAULT`), a DRP killed while Running (`daq_sim cycle --kill-drp`), and a payload byte `MemPoolSim` inverts in one L1Accept (`PSDAQ_SIM_CORRUPT_SEQ`, also in `drp_sim_frame`), which only the per-event check sees. [#43](https://github.com/carbonscott/lcls2/pull/43)
- Added the system features of a partition to the hardware-free DAQ, each run end to end with its own checks by `daq_sim feature a|b|c|d|e` (`psdaq.sim.feature`), whose report gives the Slurm job, the host, HEAD, every transition with its time and each DRP's L1Accepts as simxpm sent them against psana2's events in its stream: (a) DRPs of three types in two readout groups at different rates, `daq_sim up --also TYPE[:GROUP]` and `--fixed-rate GROUP:INDEX` (simxpm `--fixed-rates` follows a group's `L0Select_FixedRate` marker, nested as on a real XPM, and gives each DRP its own group's seq and count, `SIM:LinkL1Acc`); (b) a three-step scan driven by `psdaq/psdaq/cas/generic_timing_scan.py` over `epix100_0:user.start_ns`, the step values recorded by the timing DRP (tb) and read back by psana2; (e) `drp_bld` with `drp_pva`, `drp_udpencoder` and `epicsArch` beside a PGP DRP, `daq_sim up --bld`: `drp_bld -d sim://` takes its timing from simxpm, and `simxpm --bld` is an LCLS-II style BLD source that sends one packet per L1Accept by multicast on 127.0.0.1 with TTL 1 to a group outside 239.255.0.0/16, checked value by value by `sysdrp_check --bld`; (c) the MEB serving events to AMI with AMI showing live detector data: `daq_sim up --ami` and one cycle with `--ami-shot`, the report giving fakecam_0's DAQ and psana2 counts, `MEB_EvtCt`, `ami_check` (every event AMI computed from the MEB against psana2's) and the screenshot of AMI's own GUI showing the camera while Running. `daq_sim feature --check-only --break` shows each check failing (c: `ami-tamper`, one pixel of the result fetched from AMI). `daq_sim up --hosts A,B --dry-run` prints one partition over two nodes (not yet run); (d) `daq_sim feature d --hosts A,B` is NOT AVAILABLE unless both are hosts of the Slurm job, and with two prints that plan and fails: the two-node run is not done. `daq_sim up` refuses a mix of DRP types that cannot connect on one node: `configdb/barrier.py` makes the xpmdet, opal and piranha4 DRPs wait at Connect for every DRP on the node. ### Changed

- Changed `daq_sim coverage` so programs whose own log never names a run count from a witness the cycle wrote and the record lists: the AMI rows from `logs/ami_check.json` (the run, AMI's per-event matches with psana2, every timestamp an L1Accept of the run's file, and the processes that held AMI's ports, the row's program among them with the pid its log gives), GUI and monitor rows (`groupca`, `partca`, `pvant`, `procstat`, `epics_exporter`) from `logs/gui_witness.json` (`psdaq.sim.gui_witness` runs each GUI offscreen through `qt_walk` while the run is Running and keeps the partition PVs it showed changing, procstat's table of the run's processes RUNNING, and epics_exporter's gauges, all within the run's L1Accepts), and STAND-IN PV servers from the same witness's `servers` (read under the stand-in's prefix, with the program's PV names served); a log may also name the run's xtc2 file by its path relative to the record's `data_dir`, as `control_gui` does, if it resolves to the hashed file. `daq_sim up --gui` also runs `partca`, `pvant`, `procstat` and `epics_exporter`, and returns once `control_gui` polls control (one built after the partition is selected exits at DEBUG on `QWPopupTableCheck`'s `logger.debug('list2d\n', list2d)`); `daq_sim cycle --ami-shot PNG` saves AMI's own viewer of the camera image, run offscreen in a second `ami-client` (`psdaq.sim.ami_shot`, window grabs by `psdaq/psdaq/sim/qtgrab`). `daq_sim up --pvservers` runs `simhsd` and `simtpr` on PVA ports of their own, and the cycle's witness shows each serving every PV name `hsdpvs` and `tprcas` define, its counters live during the run: `hsdpvs` and `tprcas` are STAND-IN; with `--gui` it also runs `simdti` and the GUIs on the three stand-ins, `hsdpva`, `tprca` and `dtica`, offscreen, each searching only its stand-in's PVA ports, and coverage counts those RUN from a `gui_witness` entry that names the stand-in, whose own log the record lists, and shows one widget's PV under the stand-in's `-P` prefix take 2 or more values during the run (R4). The parity walk lets a GUI connect to this host's own name and addresses (procstat's procmgr does). Rows with no source in the tree (`hsdca`, `hsdcas`, `xpmpvas`, `tmo_acr_opal_feedback`) are N/A with the config line that names them. [#41](https://github.com/carbonscott/lcls2/pull/41)
- Changed `daq_sim coverage` so an evidence record proves a row only if its files show the row ran: the record keeps each listed file's size and sha256 from when it was written, and a file changed since (a log may only grow) or not hashed voids it; a detector row needs a listed xtc2 file, read by the tool itself, whose Configure has a detector of that type, with at least 1000 L1Accepts holding its data and a BeginRun whose runinfo is the record's run, and a log of the DRP of that type naming the run; a program row needs that program's log (its stand-in's for a STAND-IN row) naming the run's xtc2 file or BeginRun time. `daq_sim up` heads each service's log with its `# CMDLINE:`, `daq_sim cycle` prints any row coverage would reject in the record it writes, and a rejection names the kind of file problem (`not xtc2`, `changed`, ...). [#38](https://github.com/carbonscott/lcls2/pull/38)
- Changed the web GUI parity check so the offscreen PyQt walk decides which controls the running GUI builds (a mapped row it never builds fails), every web test records the backend it ran against, and a mapped row counts only if its passing test ran against the simulated DAQ; `daq_sim up --segments N` runs a fakecam detector with N segments. [#33](https://github.com/carbonscott/lcls2/pull/33)
- Changed the TEB, MEB and DRP to detect a reused or overwritten RDMA buffer slot when it happens and report the source, slot and pulse IDs; `-k eb_slot_check=0` turns this off. @rclaus2 [#289](https://github.com/slac-lcls/lcls2/pull/289)
- Changed control's BeginRun phase 1 timeout from 6 s to 12 s, since fetching calibration constants can take several seconds. @rclaus2 [#269](https://github.com/slac-lcls/lcls2/pull/269)
- Changed the DAQ and psana tests to run on every push to a PR. @mavaylon1 [#267](https://github.com/slac-lcls/lcls2/pull/267)

### Fixed

- Fixed scans recording `step_value` 0.0 in every step when the scan script yields numpy numbers (the `np.arange` values of `generic_timing_scan.py`, `epixhr_timing_scan.py`, `epixhr_r0acq_scan.py`, `epixhr_config_scan.py`): `ControlDef.MyFloatPv.update` kept only values whose type is exactly `float` or `int`; it now takes any real number. [#42](https://github.com/carbonscott/lcls2/pull/42)
- Fixed `monReqServer` aborting at Disconnect ("MEB thread lost connection with a DRP") when the DRPs dropped their links before it stopped its thread: after it has built Unconfigure, a lost link now ends the thread; before Unconfigure it still aborts. [#41](https://github.com/carbonscott/lcls2/pull/41)
- Fixed psana SMD callbacks restarting their step and event counters at chunk boundaries, which could skip selected steps or repeat event-selection windows in serial and MPI processing. @monarin [#287](https://github.com/slac-lcls/lcls2/pull/287)
- Fixed parallel psana hanging silently when the MPI layout leaves an EventBuilder with no BigData ranks. `Communicators` now rejects such layouts up front with the numbers spelled out. @amandashack [#249](https://github.com/slac-lcls/lcls2/pull/249)
- Fixed a multi-lane DRP stalling silently when one lane stops delivering, as in #273. The reader now logs, once, which lanes arrived and which are missing for the stuck event, and counts it in the `drp_num_lane_stalls` metric. A partial event left by the stall no longer survives a Reset or an evtCounter restart, where it used to combine with the next event into a duplicate transition and abort the DRP; such events are counted in `drp_num_stale_events`. @rclaus2 [#282](https://github.com/slac-lcls/lcls2/pull/282)
- Fixed `XtcMonitorServer` and `ShmemClient` not saying why `mq_open` failed. They now name the exceeded system limit (e.g. `fs.mqueue.msg_max`) or other cause and how to fix it, and errors no longer appear ahead of earlier output in logs. @rclaus2 [#276](https://github.com/slac-lcls/lcls2/pull/276)
