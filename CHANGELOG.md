### Added

- Added hardware-free runs of the XpmDetector types through `xpmdet_config.py`, which now programs an emulated TDet timing receiver (`l2si_drp.DrpTDetRoot` on `psdaq.sim.rogue_dev`, free-running counter seeds) under `drp -d sim://` instead of being skipped, simxpm keeping the timing link: fakecam and `daq_sim up --det cspad|epixhremu|jungfrauemu|ts`, with `cspad_raw_2_0_0` in psana, the frame epixhremu replays written from the seed, the timing system's `TimingData` message in `MemPoolSim`, and the PVs `ts_config`/`ts_connect` use (link, trigger and inhibit PVs, `FwBuild`) in simxpm; and hrencoder and epixm320 through their own `hrencoder_config.py` and `epixm320_config.py` (`daq_sim up --det hrencoder|epixm320`). `xtc2_check` checks each type's psana interface event by event. [#36](https://github.com/carbonscott/lcls2/pull/36)
- Added hardware-free runs of BEB detector types through their own `<type>_config.py`: `psdaq.sim.rogue_dev` emulates the device under `drp -d sim://` (rogue's PCIe map and DMA lanes with an SRPv3 responder, the driver's /proc text, and the front-end IOC's PVs for types configured over Channel Access) with per-type seeds and a fault hook that makes one named register read back wrong; `MemPoolSim` frames each type's EventBatcher subframes with pixels that depend on their position, and `xtc2_check` compares every pixel or sample through the type's psana interface; `daq_sim up --det epix100|wave8|wave8he`. `daq_sim coverage` now counts only a clean run at HEAD that names its run and whose files are non-empty and, for xtc2, whole datagram chains. [#34](https://github.com/carbonscott/lcls2/pull/34)
- Added `daq_sim coverage`, a coverage check whose rows come from source at the commit it runs on (every DRP factory registration and every program a procmgr config under `psdaq/psdaq/cnf` starts) and which passes only when each row is RUN or STAND-IN with an evidence record stamped with that commit, or N/A with a reason; `daq_sim cycle` writes the record for what it ran, and `daq_sim matrix` runs the check. [#32](https://github.com/carbonscott/lcls2/pull/32)
- Added the config DB editor (select, tree and text editors, long-value popup, save with confirm) and the rest of the PyQt control GUI's user-facing controls (partition-table columns and segment collapse, state box that ignores arrow keys and the wheel, mnemonics) to the web GUI, with a parity check that enumerates the PyQt controls from source and passes only when every row is mapped to a web element with a passing, tagged headless-browser test or is not applicable with a reason an offscreen PyQt walk confirms; `daq_sim e2e --edit-seed` (a config edit in the web editor read back at the next Configure) and `--break truncate-xtc2`; the web GUI also offers the User/Expert tabs of `CGWMainTabs`/`CGWMainTabUser`, modules the live PyQt GUI no longer imports. [#31](https://github.com/carbonscott/lcls2/pull/31)
- Added a web control GUI for the DAQ beside the PyQt one (`daq_webgui`, `psdaq/psdaq/webgui`): a loopback-only stdlib HTTP + server-sent-events server on `DaqControl` and a vanilla-JS page with the main window's controls and an events counter fed by the timing source; `daq_sim up --webgui`; `daq_sim e2e`, a one-command headless-browser test that takes the hardware-free DAQ to Running and back through the web GUI and checks that the page count, the TEB written count and psana2's count agree; and a parity enumerator and checker over `psdaq/psdaq/control_gui`. [#30](https://github.com/carbonscott/lcls2/pull/30)
- Added a hardware-free DAQ on one node: `simxpm`, a simulated XPM that serves the PVs control.py writes and sends ordered timing frames; a `sim://` DMA backend for the CPU DRP (`MemPoolSim`, `drp -d sim://host:port`) with a fakecam payload checkable per event; `daq_sim up/cycle/status/down` to run control (normal mode), the TEB and a simulated DRP under procmgr; `xtc2_check` for psana2 read-back; and `psdaq/psdaq/sim/RUNBOOK.md`. [#29](https://github.com/carbonscott/lcls2/pull/29)
- Added `psdaq.sim` local stand-ins for running the DAQ with no hardware on one node: a config DB server with `mongoconfigdb` semantics backed by a JSON file, a seed for the `tmoteb` trigger and a `fakecam` sim detector, a run DB/eLog stub, and an isolation env (`sim_env.sh`) with a fail-closed `preflight.sh`. [#28](https://github.com/carbonscott/lcls2/pull/28)
- Added ePixUHR calibration and a CALIB mode for taking darks to the GPU DRP, with the Reader/Reducer performance work that runs five GPU DRPs on one node at 33 kHz, and per-stage metrics. @rclaus2 [#269](https://github.com/slac-lcls/lcls2/pull/269)

### Changed

- Changed `daq_sim coverage` so an evidence record proves a row only if its files show the row ran: the record keeps each listed file's size and sha256 from when it was written, and a file changed since (a log may only grow) or not hashed voids it; a detector row needs a listed xtc2 file, read by the tool itself, whose Configure has a detector of that type, with at least 1000 L1Accepts holding its data and a BeginRun whose runinfo is the record's run, and a log of the DRP of that type naming the run; a program row needs that program's log (its stand-in's for a STAND-IN row) naming the run's xtc2 file or BeginRun time. `daq_sim up` heads each service's log with its `# CMDLINE:`, `daq_sim cycle` prints any row coverage would reject in the record it writes, and a rejection names the kind of file problem (`not xtc2`, `changed`, ...). [#38](https://github.com/carbonscott/lcls2/pull/38)
- Changed the web GUI parity check so the offscreen PyQt walk decides which controls the running GUI builds (a mapped row it never builds fails), every web test records the backend it ran against, and a mapped row counts only if its passing test ran against the simulated DAQ; `daq_sim up --segments N` runs a fakecam detector with N segments. [#33](https://github.com/carbonscott/lcls2/pull/33)
- Changed the TEB, MEB and DRP to detect a reused or overwritten RDMA buffer slot when it happens and report the source, slot and pulse IDs; `-k eb_slot_check=0` turns this off. @rclaus2 [#289](https://github.com/slac-lcls/lcls2/pull/289)
- Changed control's BeginRun phase 1 timeout from 6 s to 12 s, since fetching calibration constants can take several seconds. @rclaus2 [#269](https://github.com/slac-lcls/lcls2/pull/269)
- Changed the DAQ and psana tests to run on every push to a PR. @mavaylon1 [#267](https://github.com/slac-lcls/lcls2/pull/267)

### Fixed

- Fixed psana SMD callbacks restarting their step and event counters at chunk boundaries, which could skip selected steps or repeat event-selection windows in serial and MPI processing. @monarin [#287](https://github.com/slac-lcls/lcls2/pull/287)
- Fixed parallel psana hanging silently when the MPI layout leaves an EventBuilder with no BigData ranks. `Communicators` now rejects such layouts up front with the numbers spelled out. @amandashack [#249](https://github.com/slac-lcls/lcls2/pull/249)
- Fixed a multi-lane DRP stalling silently when one lane stops delivering, as in #273. The reader now logs, once, which lanes arrived and which are missing for the stuck event, and counts it in the `drp_num_lane_stalls` metric. A partial event left by the stall no longer survives a Reset or an evtCounter restart, where it used to combine with the next event into a duplicate transition and abort the DRP; such events are counted in `drp_num_stale_events`. @rclaus2 [#282](https://github.com/slac-lcls/lcls2/pull/282)
- Fixed `XtcMonitorServer` and `ShmemClient` not saying why `mq_open` failed. They now name the exceeded system limit (e.g. `fs.mqueue.msg_max`) or other cause and how to fix it, and errors no longer appear ahead of earlier output in logs. @rclaus2 [#276](https://github.com/slac-lcls/lcls2/pull/276)
