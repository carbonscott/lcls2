Findings

  1. An upstream change to import scoping broke a fork-only caller. a8f908d56 made epix-100a-gen2 importable only inside firmware_packages.isolated(); the fork's configdb seed relied on the old global import. sim-main alone does not have a8f908d56, so only the merge hit it. Any other fork code that imports a firmware package's Python outside isolated() can fail the same way (not verified: no search of the fork was made for this page).
  2. One failure hid eight rows. In the before run the matrix failure kept 8 weekly rows from running; the suite records them as FAIL with not run: evidence. Their after-run verdicts are the first evidence on those rows at this merge.
  3. The e2e failure was the fork's own test harness (known defect #63), not the web GUI or the DAQ: the scrape got a tuple as its port and swallowed the error.
  4. The epixquad edit is now upstream, so its guard and probe failed by design; retiring them (decision 2) is a suite change with an approval record, not a fork change.
  5. drift/kinds and drift/unseeded needed a new baseline, which the owner approved. In the first run at this head (eafdc1303179-20261120T182254Z-dw) both FAILed against baseline 08a6634c874b: upstream a8f908d56 (slac-lcls/lcls2#252) builds epix100's and epixquad1kfps' PCIe-card register tree from the card's own surf, so the DAQ now reads that card with its own register map (epix100 +10/-129 kinds, epixquad1kfps +35/-321; identical in every run). The owner approved the update ("continue, approve!", 2026-11-20T19:52Z; approvals/20261120-pr71-kinds-unseeded-baseline.json in carbonscott/lcls2-sync#1).
  6. The new baseline is recorded from two runs at this tree. baselines/eafdc1303179/kinds.json is the intersection of runs eafdc1303179-20261120T182254Z-dw and eafdc1303179-20261120T195304Z-dw.
